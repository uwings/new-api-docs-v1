## 概述

aididai.cn 基于开源 API 网关项目构建，整体架构可以理解为三层：**前端控制台**、**API 网关**、**上游 AI 服务商**。用户只需要关注最前方的接入部分，背后的路由和转发由平台自动完成。

## 请求链路

当你发起一次 API 调用时，请求会经过以下路径：

<Steps>
  <Step title="你的应用 → 平台 API 网关">
    你的代码向 `https://aididai.cn/v1/chat/completions` 发送请求，
    携带平台签发的 API Key。网关验证令牌、检查额度、记录调用。
  </Step>
  <Step title="网关 → 上游 AI 服务商">
    网关根据你请求的模型名称，将请求转发到对应的上游服务商
    （OpenAI、Anthropic、DeepSeek 等）。这一步对你是透明的。
  </Step>
  <Step title="上游返回 → 网关 → 你的应用">
    上游模型返回结果后，网关统计 Token 消耗、扣除额度，
    然后将标准 OpenAI 格式的响应原样返回给你的应用。
  </Step>
</Steps>

## 对你来说意味着什么

<Callout type="info" title="你不需要关心的事">
  - 上游服务商有哪些、怎么配置
  - 请求被路由到哪个节点
  - 网关的负载均衡和故障切换逻辑
  - 令牌权限和模型访问控制的后端实现
</Callout>

你只需要：

1. 在控制台注册并创建令牌
2. 将 Base URL 指向 `https://aididai.cn`
3. 在请求中指定要使用的模型名称
4. 像调用 OpenAI 一样编写你的代码

## 延迟说明

由于请求需要经过网关转发到上游服务商，实际延迟由两部分组成：

- **网关处理**：通常在几十毫秒级别，可忽略
- **上游模型推理**：取决于模型本身和当前负载，这是主要瓶颈

如果你使用的是国外模型（如 GPT-4、Claude），可能因为网络链路增加少量延迟。使用国产模型（如 DeepSeek、Qwen）通常延迟更低。

## 为什么用网关而不是直连

对于公益站用户来说，通过网关而不是各自注册上游账号有几个好处：

- **零成本**：不需要注册 OpenAI、Anthropic 等服务商账号
- **无需海外信用卡**：很多上游服务需要海外支付方式
- **统一管理**：一个令牌调用所有模型
- **格式统一**：不同上游的 API 差异由网关抹平，你看到的始终是 OpenAI 格式
