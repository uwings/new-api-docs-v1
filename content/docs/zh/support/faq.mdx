## 💰 额度相关问题

<Accordions>
  <Accordion title="额度是什么？怎么计算的？">
    额度计算公式如下：

    ```
    额度 = 分组倍率 * 模型倍率 * （提示 token 数 + 补全 token 数 * 补全倍率）
    ```

    **补全倍率说明：**
    - GPT3.5：固定为 1.33
    - GPT4：固定为 2（与官方保持一致）

    **注意事项：**
    - 非流模式下，官方接口会返回消耗的总 token，但提示和补全的消耗倍率不同
    - 公益站的默认倍率与官方倍率一致，已经过调整
  </Accordion>

  <Accordion title="账户额度足够为什么提示额度不足？">
    这是因为令牌额度和账户额度是分开的：

    - 令牌额度仅用于设置最大使用量限制
    - 用户可以自由设置令牌额度
    - 请检查您的令牌额度是否充足
  </Accordion>

  <Accordion title="公益站每天有多少免费额度？">
    不同用户分组享有不同的额度配额，具体取决于站点运营策略和您的用户分组。

    - 注册用户通常享有基础免费额度
    - 额度每日按站点规则补充或重置
    - 您可以在控制台首页查看当前剩余额度和用量明细
    - 如需更高额度，可关注站点公告了解升级方式
  </Accordion>
</Accordions>

## 🆓 关于公益站

<Accordions>
  <Accordion title="为什么这个站是免费的？">
    本站为公益性质 AI API 中转站，由社区维护，面向学习者和开发者免费提供 API 服务。

    - 运营成本由社区赞助和志愿者承担
    - 目标是降低 AI 使用门槛，让更多人能体验大模型能力
    - 站点不承诺 100% 可用性，请勿用于关键生产环境
    - 公益站资源有限，我们希望将额度留给真正有学习需求的人
    - 如需查看运营成本来源和资金明细，可关注站点公告中的透明度报告
  </Accordion>

  <Accordion title="为什么会有限流？超出额度怎么办？">
    限流是为了保证所有用户都能公平使用有限的资源。

    **限流策略：**
    - 每个用户有每日请求频率上限和额度上限
    - 热门模型可能设置更严格的并发限制
    - 超出限制时接口会返回 `429` 错误，提示「请求过于频繁」或「负载已饱和」

    **超出额度后可以：**
    - 等待额度恢复（通常次日重置）
    - 切换到消耗更低的模型
    - 优化请求内容，减少不必要的 token 消耗
    - 关注站点公告，部分站点会不定期开放额外额度
    - 如果您是学生或研究者，可联系管理员申请专项额度支持
  </Accordion>

  <Accordion title="故障或维护时去哪里查看状态？">
    当遇到接口异常、请求失败或服务不可用时，请按以下顺序排查：

    1. **查看站点公告**：控制台首页通常会展示维护通知和故障说明
    2. **加入社区频道**：Telegram / QQ 群组会在第一时间发布故障通告
    3. **检查接口返回的错误码**：根据错误码判断是额度问题、限流还是服务端故障
    4. **确认不是自己的问题**：检查 API Key 是否正确、网络是否通畅

    请注意，公益站没有专职运维团队，故障恢复时间可能较长，请耐心等待公告。
  </Accordion>

  <Accordion title="我的数据安全吗？">
    公益站对数据安全的处理方式如下：

    - **对话内容**：请求内容仅用于转发给上游模型，站点不会主动存储您的对话记录
    - **日志保留**：系统会记录请求日志（时间、模型、token 用量等）用于额度统计和故障排查，通常保留 7-30 天
    - **API Key 安全**：请妥善保管您的 API Key，泄露后请立即重置
    - **上游隐私**：您的请求会转发至上游 API 提供商（如 OpenAI、Anthropic 等），其隐私政策适用
    - **公益站性质**：站点由志愿者维护，无法提供企业级数据安全保证，请勿提交敏感信息或商业数据
    - **建议**：使用前请评估您的数据隐私需求，敏感场景建议使用官方付费 API
  </Accordion>

  <Accordion title="账户被封了如何申诉？">
    如果您的账户被禁用，可能是以下原因：

    - 违反了公益站使用条款（如滥用、恶意刷量、多账号）
    - 请求内容违反使用政策
    - 异常请求行为触发自动封禁

    **申诉方式：**
    - 在社区频道（Telegram / QQ 群）联系管理员，说明您的用户名和封禁情况
    - 诚恳说明情况，承诺遵守使用规范
    - 管理员会根据情况决定是否解封

    **常见封禁类型与处理：**
    - **额度滥用**：短时间大量消耗、频繁切换多账号 → 首次封禁可申诉解封
    - **内容违规**：生成违规内容 → 视严重程度处理
    - **商用/倒卖**：将额度用于商业服务或转售 → 通常永久封禁，不予解封

    请注意，恶意违规（如倒卖额度、大规模商用）通常不予解封。
  </Accordion>

  <Accordion title="可以用于商业用途吗？">
    公益站原则上**不支持商业用途**。

    - 公益站资源由社区赞助，目的是服务学习和个人探索
    - 严禁将公益站额度用于商业产品、对外服务或批量自动化任务
    - 严禁倒卖、转售公益站 API Key 或额度
    - 严禁接入自动化爬虫、批量内容生成等高频任务
    - 如有商业需求，请使用官方 API 或付费服务商

    违规商用行为会被检测并封禁账户。
  </Accordion>

  <Accordion title="怎么反馈问题或提建议？">
    欢迎通过以下方式反馈：

    1. **提交 GitHub Issue**：在 [GitHub 上提交 issue](/zh/docs/support/feedback-issues)，描述问题复现步骤
    2. **社区频道反馈**：在 Telegram / QQ 群组中直接与维护者沟通
    3. **提交功能建议**：GitHub Issue 中也可以提交功能建议和改进想法

    反馈时请尽量包含：

    - 错误信息或异常表现
    - 请求时间（大致）
    - 您的用户名或 API Key 后四位（便于排查）

    我们会认真对待每一条反馈，但受限于志愿者精力，回复可能不及时，请见谅。
  </Accordion>

## ⚡ 使用问题

<Accordions>
  <Accordion title="提示「当前分组负载已饱和，请稍后再试」是什么意思？">
    这表示上游渠道出现了 429 错误（请求过多），通常是高峰期请求量过大导致。

    **建议处理方式：**
    - 稍后重试，避开高峰时段
    - 尝试切换其他可用模型
    - 减少请求频率，避免短时间内大量并发
  </Accordion>

  <Accordion title="ChatGPT Next Web 等客户端报错：Failed to fetch">
    请检查以下几点：

    1. 确认接口地址填写正确（公益站分配的 Base URL）
    2. 确认 API Key 填写正确且未过期
    3. 检查是否启用了 HTTPS（浏览器会拦截 HTTPS 页面下的 HTTP 请求）
    4. 确认账户额度是否充足
    5. 确认未触发频率限制
    6. 检查网络环境是否需要代理（部分网络环境下直连可能超时）
  </Accordion>

  <Accordion title="为什么有些模型用不了？">
    可能的原因：

    - 该模型未对您的用户分组开放
    - 该模型对应的上游渠道暂时不可用或已下线
    - 站点管理员未配置该模型的倍率
    - 您的额度等级不支持使用该模型

    请查看站点公告或控制台模型列表了解当前可用模型。
  </Accordion>

  <Accordion title="请求很慢怎么办？">
    响应速度受多种因素影响：

    - **上游模型负载**：高峰时段 OpenAI 等上游服务本身可能变慢
    - **模型类型**：推理模型（如 o1）响应时间天然较长
    - **请求大小**：超长 prompt 会增加处理时间
    - **站点负载**：公益站高峰期资源紧张

    **优化建议：**
    - 避开高峰时段使用
    - 精简 prompt，只保留必要上下文
    - 优先使用响应更快的模型
    - 如持续超时，请通过社区频道反馈
  </Accordion>
</Accordions>
