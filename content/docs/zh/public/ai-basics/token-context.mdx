## Token 是什么

**Token 是大模型处理文本的最小单位。** 不是"字"也不是"词"，而是介于两者之间的碎片。

粗略规则：
- **英文**：1 个 token ≈ 0.75 个单词。约 1000 tokens ≈ 750 词
- **中文**：1 个汉字 ≈ 1.5-2 个 token。约 1000 个汉字 ≈ 1500-2000 tokens

举例：

```
"你好世界" → 大约 6 tokens
"Hello, how are you?" → 大约 6 tokens
```

> 为什么中文更"贵"？因为 tokenizer（分词器）主要按英文训练，中文字符比较"陌生"所以切得更细。

## Token 和费用

API 调用按 token 用量计费。每个模型都有单价，通常分为：

| 费用类型 | 含义 |
|---------|------|
| 输入 token | 你每次发送给模型的内容（包括历史对话） |
| 输出 token | 模型生成给你的回复 |

每次调用 = 输入费用 + 输出费用。

> 公益站目前**完全免费提供**，但你理解 token 概念会帮助你有意识地节约使用。长轮对话时记得清理不必要的历史消息。

## 上下文窗口

**上下文窗口 = 模型一次能"看到"的最大 token 数**，包括你的问题和它要生成的回答。

| 模型 | 上下文窗口 |
|------|-----------|
| gpt-3.5-turbo | 16K tokens（约 8000 个汉字） |
| gpt-4、gpt-4o | 128K tokens（约 6.5 万个汉字） |
| deepseek-chat | 64K tokens（约 3.2 万个汉字） |

超出上下文窗口的文字会被丢弃，模型"看不到"。

**实际影响**：
- 上传一本书给 gpt-3.5-turbo → 超出窗口，后面的内容被截断
- 对话轮数太多 → 早期内容被挤出窗口，模型"忘了"前面聊的什么
- 需要处理长文档 → 选大窗口的模型（gpt-4o 或 deepseek-chat）

## 实战技巧

### 省 Token 的写法

```bash
# 不好 — System Prompt 太长，占用大量输入 token
"system": "你是一个专业的AI助手，擅长编程、写作、翻译、分析数据..."  # 200 tokens

# 好 — 精简，说清楚要什么
"system": "你是一个Python编程助手。回答简洁，给代码。"  # 15 tokens
```

### 长对话怎么管

- 不需要的早期对话内容，**开新对话**而不是在同一个窗口继续
- 长文本可以先让模型总结摘要，再把摘要发给新对话窗口继续
- 用 `system` prompt 告诉模型"只回答我最后的问题，前面的是背景"
